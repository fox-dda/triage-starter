# Валидация входящих заявок и безопасная ручная обработка при сбое AI

Некорректный ввод теперь возвращает HTTP 400 с `invalid_input`. Для корректной
заявки сервер возвращает только проверенные тему и черновик. Таймаут 300 мс,
ошибка провайдера, битый JSON или неверная структура результата дают HTTP 200
с `manual_review`, `topic: null`, `draft: null`.

На странице менеджер видит русское название темы и черновик, который нужно
проверить перед отправкой. При новой обработке прежний результат очищается;
при сбое показывается сообщение о необходимости обработать заявку вручную.

- Результат AI проверяется в `handleTriage` в `server.mjs`, до формирования
  ответа API: разрешены только `delivery`, `pricing`, `other` и непустой
  строковый `draft`. Посторонние поля модели не попадают в ответ.
- При таймауте срабатывает `Promise.race` и отмена через `AbortController`.
  Ограничение работает и с провайдером, игнорирующим сигнал отмены.
- Использован OpenAI Codex (GPT-6) для реализации, тестов и документации.
  Рабочий классификатор — исходный локальный имитатор, внешние AI API и ключи
  приложению не нужны. `mock-ai.mjs` не изменён.
- Автоматически проверены HTTP-контракт, все сценарии имитатора, таймаут,
  восстановление, фильтрация полей и поведение скрипта страницы: 6 тестов.
  Тест интерфейса использует имитацию DOM; визуальная проверка в браузере
  не выполнялась. Автору перед сдачей следует самостоятельно пройти сценарии
  из README и ознакомиться с кодом; такая проверка пользователем пока
  не подтверждена.

Запуск (Node.js 20+, без зависимостей): `node server.mjs`, затем открыть
http://127.0.0.1:3000. Тесты: `node --test triage.test.mjs`.

Польза: менеджер быстрее готовит ответ; измерить её можно по медианному времени
от открытия заявки до готового, проверенного менеджером ответа.

Публикация PR пока не выполнена: нужен реальный учебный репозиторий и доступ
к нему. Локальная история содержит исходный коммит в `main` и реализацию
в ветке `feat/triage-validation`.
